# Public Repository and Website Publication Checklist

Repository visibility and website access are separate controls. Complete the
relevant section before changing either one.

## Public repository

- [ ] Review every tracked file and binary asset.
- [ ] Review every reachable Git commit, not only the latest snapshot.
- [ ] Remove precise addresses, private financial data, credentials, personal
      data, and unpublished business records from current files.
- [ ] Rewrite or replace Git history if earlier commits contain information that
      should not be republished.
- [ ] Confirm commit-author names and email addresses are acceptable publicly.
- [ ] Confirm all website copy is approved for public discovery through source.
- [ ] Confirm all images and fonts have publication and redistribution rights.
- [ ] Confirm repository ownership, CODEOWNERS, and the proprietary license.
- [ ] Confirm no external contribution expectation is created.
- [ ] Set a repository description, homepage, and topics.
- [ ] Enable secret scanning and appropriate branch protections when available.
- [ ] Obtain explicit authorization from Equis Nexus management.

## Public website

- [ ] Approve company name, legal form, mission, vision, and contact details.
- [ ] Complete legal review of financial, valuation, and forward-looking copy.
- [ ] Confirm every asset fact against its stated source.
- [ ] Keep exact amounts and transaction records outside the website bundle.
- [ ] Approve every image for public use.
- [ ] Add privacy and legal notices required for the intended audience.
- [ ] Confirm accessibility, mobile presentation, metadata, and language quality.
- [ ] Decide whether analytics are needed and review consent obligations first.
- [x] Obtain explicit approval before changing Sites access from owner-only.
